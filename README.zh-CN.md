# Personal Plans

**把目标、每日计划、完成反馈与重复安排，保存在你自己掌控的资料中。**

[English](README.md) · [Skill 指令](SKILL.md) · [参与贡献](CONTRIBUTING.md) · [MIT 许可证](LICENSE)

Personal Plans 是一个指导 Agent 管理长短期计划的 Skill：将目标拆解为里程碑和行动，安排时间，记录结果，再生成有依据的复盘。数据通过 Agent 已有的工具保存到你指定的 Git 仓库，仅管理 `plans/`，可与 [Personal Atlas](https://github.com/Charlie-BU/Personal-Atlas) 等个人 Skill 共用仓库。

本项目只分发技能，**不存放你的个人资料**。Skill 指令主要为中文，项目说明提供中英双语。

## 能做什么

- 连接长期目标、阶段里程碑、单次任务和独立重复实例；每条计划都有四象限优先级与理由。
- 区分安排、期限、原始期限和实际完成时间；没有反馈保持未知，不自动判为失败。
- 为每项计划、每天、周、月、季度、年和自定义周期保存备注、补充说明与完成反馈；区分用户原话和 Agent 观察。
- 用紧凑索引定位，再读取并校验原文；不依赖向量数据库。
- 远端保存 cronjob 定义、调度绑定和运行回执，让其他有相应能力的 Agent 可以核查和接续。
- 提议将有来源的目标、成果或偏好交给 Atlas，由用户决定；不自动同步画像。

## 使用示例

> 半年内完成作品集，先拆出本周的阶段目标，每两天安排一次项目整理。

> 今天的整理完成了。备注：示例很有帮助，但介绍部分还需要更多时间。

> 复盘本季度，结合我写的补充说明，区分已确认完成和尚未反馈的内容。

查看计划、目标、日程、搜索结果和周期完成情况时，默认采用简洁表格并保留“备注/补充”列；提醒同样遵循。用户明确指定其他格式时遵从，无记录直接说明，渠道不支持表格时使用等价卡片或紧凑分行展示。以下为**虚构展示**：

| 时间 | 计划 | 优先级 | 状态 | 备注/补充 |
| --- | --- | --- | --- | --- |
| 09:00–10:00 | 筛选作品集案例 | 重要不紧急 | 待完成 | 先选三个项目 |
| 晚上 | 整理一个项目 | 重要不紧急 | 待安排 | — |

早间任务既提醒已有计划，也提醒设立或补充当日计划。表格是 Agent 的输出规范，本项目没有附带图形化计划应用。

## 安装

将仓库克隆到宿主技能目录下的 `personal-plans`，或使用宿主的 Skill 导入能力。本地 Codex 示例：

```sh
git clone https://github.com/Charlie-BU/Personal-Plans.git ~/.codex/skills/personal-plans
```

已有安装请先检查，不直接覆盖。保持 `SKILL.md`、`references/`、`scripts/`、`agents/` 在同一目录。宿主需支持 Agent Skill，并按需提供 Git、日历、定时执行和通知工具；这不是 MCP 服务，也不会自行启动后台进程。

计算脚本需要 Python 3.9+：

```sh
python3 -m pip install -r ~/.codex/skills/personal-plans/scripts/requirements.txt
```

系统 Python 要求时使用虚拟环境。依赖仅有处理重复规则的 `python-dateutil`，以及为缺少系统时区库的环境提供数据的 `tzdata`。

## 首次使用

可以这样告诉 Agent：

> 使用 Personal Plans。个人数据仓库是 `https://github.com/YOUR-NAME/YOUR-PRIVATE-DATA`，时区是 Asia/Shanghai。先核对连接，再从作品集目标开始引导我。

Onboarding 会核对资料仓库、时区、所选日历与第一条计划。有效资料复用，不影响其他目录。日历通过宿主工具实际验证；缺少日历或调度能力时明确说明，不妨碍先讨论和在仓库能力可用时保存计划。

非凭据连接信息保存在 Skill 外的 `~/.config/personal-plans/config.json`；凭据留在宿主授权连接中，不在聊天索要令牌，也不提交本项目。

引导会告知两项默认设置，按用户时区运行：

| 任务 | 默认时间 | 职责 |
| --- | --- | --- |
| 早间计划 | 08:00 | 提醒已有计划，并提醒设立或补充当日计划 |
| 晚间复盘 | 21:00 | 汇总已确认结果、调整、未知项与备注 |

两项都能单独关闭或改时。用户接受已告知的设置、明确授权本人渠道后保存默认配置。**配置 enabled 不等于调度已连接，更不等于消息已触达。** 还需宿主注册或复用真实任务、回读核验并保存绑定；测试消息须获授权。每周复盘、阶段目标检查仅作可选提议。

## 数据怎样存、怎样读

```text
个人资料仓库/
├── atlas/                         # 其他 Skill 管理
├── plans/
│   ├── vault.json
│   ├── goals/                     # 目标与里程碑
│   ├── tasks/                     # 单次任务与重复模板
│   ├── occurrences/YYYY-MM/       # 已保存的实例与例外
│   ├── periods/                   # 每日、任意周期的原始反馈
│   ├── activities/                # 修改、原因及前后状态
│   ├── operations/                # 操作去重
│   ├── cronjobs/                  # 定义、执行器绑定、运行回执
│   ├── indexes/catalog/           # 最多16个“条件→ID”分片
│   ├── indexes/records/           # 最多16个唯一记录卡片分片
│   ├── manifests/                 # 原始文件内容哈希
│   └── reports/                   # 有证据快照的报告
└── health/                        # 其他 Skill 管理
```

查询固定同一个仓库提交，按日期、状态、目标、关键词等定位，读取相关卡片分片，再校验命中原文。摘要只导航，不作为事实证据。中文单字/二元组和英文词元是词法匹配，不保证语义召回。结果继续分页；分片可能含其他记录的导航信息，不等于读取其他记录原文。

写入完整校验 `plans/` 权威资料，在内存准备，之后由宿主完成受并发保护的原子 Git 提交和回读。`prepared` 只表示准备好，不代表已保存；其他 Skill 推进仓库 HEAD 也要重读重建。脚本不建立本地个人资料库、缓存或离线队列。

重复模板只展开查询范围。某次需要反馈、修改或保存结果时才物化，单次修改不重写整个系列。法定节假日和调休需要有来源的地区日历，缺覆盖不猜。

## cronjob 与换 Agent

cronjob 保存“什么时候运行、做什么”，不固化创建时的计划列表。每次运行读取远端最新计划和策略；新增、修改、完成或取消计划不用重建周期任务。时间、时区、渠道、启停或执行行为变更才需要更新配置。

接管时先核查并暂停旧调度器，再启用新执行器。每次触发有稳定身份和远端领取记录；结果未知时核查，避免盲目重发。Git 与外部消息服务不是“恰好一次”事务。跨 Agent 复用要求相应工具、仓库权限、本人渠道授权及旧调度器的可核查性，不承诺任何环境下无条件自动接管。

## 紧凑索引升级

只支持 `index_format=2`，没有旧格式读取器。已有资料库需显式执行 `reindex`：按 [storage.md](references/storage.md) 校验权威文件、重建索引、原子提交并回读验证。计划、反馈、cronjob 和其他目录保持字节不变。只更新本地 Skill 不会自动迁移远端数据。

## 开发验证

```sh
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 -B scripts/demo.py
```

测试和演示仅使用合成内存仓库，不连接账号、不写个人资料、不注册定时器、不发消息。CI 在多个 Python 版本运行测试与演示。本地协议验证不等于所有宿主和服务的真实账号端到端验收。

## 隐私与许可证

建议个人资料使用私有仓库，仅授权所需权限。不要向公共 issue 提交真实计划、凭据、通知回执或私人截图。普通删除不清除 Git 历史及外部日历/消息副本；共用仓库不自动授权跨 Skill 读取。原始反馈可支持 Atlas 提案，完成率不能直接推断人格。
