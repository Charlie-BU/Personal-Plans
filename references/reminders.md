# 主动提醒与运行时契约

Skill 是指令和纯计算工具，不是后台进程。不能因为保存了 reminders 字段、queued 意图或设置了 onboarding 标记就声称“会主动提醒”。

## 用户选择与运行环境

周期提醒、早间制定计划、晚间报告和跨 Agent 接管先读 [cronjobs.md](cronjobs.md)，配置、绑定、运行结果保存远端；本文件处理单条计划的精确提醒及发送规则。

先确定：是否启用、本人渠道别名、安静时段/时区、每日上限、精确提醒还是周期复盘、可用的调度执行器。配置明确同意的策略，保存 consent_reference；不内嵌手机号、token、凭据。停止/暂停请求优先更新策略并停用真实调度器。

优先用日历原生提醒承接精确时间；Agent 定时运行适合早晨建议、晚间询问进度、每周复盘。若宿主支持自动化，按其现有工具创建并验证；若没有则说明未启用，不自造 cron 或承诺离线/关机后准点触达。固定计划请求不意味着授权给其他人发消息。

## 有限窗口计算

读取最新 vault、reminders 策略、agenda 和已有 effects。记录 rule 规定 anchor=start/due、offset_minutes（提前为负）和用户本人 channel。只有带精确时刻的 anchor 能排定计时提醒；日期/“晚上”不能凭空解释成几点。普通自然语言回访建议由运行时根据用户策略发起，不伪装为精确定时规则。

为选定的已落库 task/occurrence 准备 notification integration：

```json
{
  "operation_id":"op_notify_unique","base_commit":"当前HEAD",
  "kind":"notification","record_id":"已落库ID","action":"send",
  "payload":{"trigger_at":"实际带偏移触发时刻","rule_id":"记录中规则ID","channel":"已选本人渠道别名"}
}
```

脚本校验 opt-in、当前规则/anchor和时刻。通知去重身份取 record_id + rule_id + trigger_at + channel，不因新增普通备注而重复通知。完成/取消/跳过、改期或规则变化会把未确认旧通知意图标为 cancelled；真正的外部提醒撤销仍需运行时调用并回读。

## 执行前必须再检查

- 最新 Git 提交中该记录仍有效，触发时刻和规则未变，用户仍授权。
- 安静时段和当日已确认发送数量没有超限。quiet_start > quiet_end 表示跨午夜；受限时跳过或延后，但不得悄悄改变用户语义，记录实际处理。
- 日历原生通知与 Agent 消息是否重复，默认同一提醒只用一个主要渠道。
- 同一资料库/渠道只有一个活跃执行器，或实际运行环境有可靠的租约/原子领取能力。单纯 Git queued 状态不能保证多进程恰好发送一次。
- 先查已有 provider 回执和去重键，再调用消息工具。不能把定时任务“执行成功”当成消息触达。

发送后回读/检查提供者实际消息 ID，再以原 intent_id 登记 confirmed receipt。超时或结果不明记 unknown，查服务端是否已发送再恢复；无查询/幂等能力时停止自动重发并报告。不要为绕过去重换 operation_id 或 trigger_at。

`effects --from ... --to ... --state queued --state unknown` 按月份/状态定位待办，返回 effect_executed=false、stale_record_revision 和 terminal_record，供执行器核对。cancelled 动作仅返回历史意图，不读取可能已删除的任务，也不包含上述两个当前记录标记，不得执行。calendar的月份按创建时间、notification按trigger_at；跨月扫描不能只看当天创建动作。

## 能力验收

测试用户明确允许的一条本人通知，核对真实渠道、服务 ID、时区、去重、完成后停止、安静时段与失败恢复。没有做真实账号测试只报告本地协议/合成测试通过；不得自动给用户发测试消息。

## 提醒展示

提醒沿用 SKILL.md 的“计划展示”规则；该规则也覆盖用户主动查看目标、日程、搜索结果和周期完成情况，不只在发送提醒时适用。

计划和周期表格预留“备注/补充”列，无记录写“—”；已有备注给简短提示并允许展开。提醒末尾可用一句话提示用户回复完成情况或补充原因，收到后按 [period-notes.md](period-notes.md) 保存，不仅用于当前聊天。

所有 Agent 生成的提醒都使用简短可视化表格或渠道支持的等价结构化卡片，覆盖早间、晚间、到期、周期和即时提醒。标题写清用户当地日期；时间有歧义时附时区。默认列为“时间/期限｜事项｜优先级｜状态”，按场景删去无关列，单条提醒也可用紧凑的字段/内容表。晚间报告用“事项｜完成情况｜需确认或下一步”。不展示内部 ID、cron 表达式或技术回执。

早间先列当日已有计划，再用一句话提醒“请设立或补充今天的计划”。无记录时明确“暂无已记录计划”，给出简短的填报提示，不生成虚构计划或空白大表；已有计划不等于已完整规划，也不称用户尚未制定。完成和未知严格区分，未定时间写“待安排”，优先级用中文易懂标签。

表格事项用短句，长备注按需展开；内容很多时分组或分批，不静默省略而声称完整。渠道不支持表格时用紧凑分行字段保持同样信息层次，不发送无法阅读的 Markdown。日历原生通知若有版式限制，使用其可展示的最简结构，并如实说明限制，不承诺任意表格渲染。
